# FreeLLMAPI integration — TV OFF

This branch adds a small OpenAI-compatible client and a manual GitHub Actions
smoke test. It does **not** change publishing schedules, upload logic, slot
deduplication, cooldowns, or the shared publishing concurrency group.

## Required gateway

FreeLLMAPI is a self-hosted gateway, not a hosted free API. It must be running
at a stable HTTPS URL that the GitHub-hosted runner can reach. Do not expose an
unauthenticated dashboard or use a public HTTP endpoint.

Configure these repository Actions secrets:

- `FREELLMAPI_BASE_URL`: gateway origin, e.g. `https://llm.example.net`
  (do not include the `/v1/chat/completions` suffix).
- `FREELLMAPI_API_KEY`: the unified `freellmapi-...` key generated by the
  gateway.

Add provider credentials (for example Google AI Studio and Groq) inside the
FreeLLMAPI dashboard, not in repository files. Configure the gateway's model
fallback chain there. Provider free-tier limits and availability still apply.

## Test

After both GitHub secrets are present, run **Actions → TV OFF — FreeLLMAPI
Connection Test → Run workflow**. A successful run confirms the runner can
reach the gateway and receive a chat completion.

## Python use

```python
from tv_off_ai import chat_completion

title = chat_completion([
    {"role": "system", "content": "Write concise, human-sounding English YouTube SEO titles."},
    {"role": "user", "content": "Create a unique title for a brown noise sleep video."},
])
```

The client defaults to model `auto`; FreeLLMAPI handles model/provider routing.
It retries only transient gateway/network failures and never prints API keys.

## Important deployment note

The GitHub-hosted runner is temporary. Starting FreeLLMAPI inside a job would
discard its database and configured provider keys when that job ends, and the
workflow would still need a gateway API key. Therefore this integration expects
a persistent gateway endpoint. Do not assume the gateway itself or provider
usage is unlimited or guaranteed free.
